## 1. 產品概覽

### 1.1 規格總表

| 規格 | 內容 |
|------|------|
| 產品類型 | 手機優先的旅遊行程共編 PWA |
| 核心模式 | **傳網址即共編** — 無需註冊，旅伴點開連結就能一起看/改同一份行程 |
| 目標平台 | Web PWA（主）；Phase 3 用 Capacitor 包 iOS 殼上架 |
| 技術骨幹 | React 18 + Vite + Tailwind（沿用 v1） |
| 後端 | Supabase（Postgres jsonb + Realtime + Storage） |
| 離線策略 | **完整 offline-first**：IndexedDB 本地優先 + 同步佇列 + 衝突合併 |
| AI 能力 | Vercel serverless 呼叫 Claude（航班時刻查詢、即時匯率） |
| 帳號 | **無登入**，以強隨機 trip key 做存取邊界 |

### 1.2 核心價值主張

| # | 主張 | v1 痛點 → v2 解法 |
|---|------|-------------------|
| 1 | **打開就在、永不掉資料** | v1 重開連結會產生新 key 洗掉資料 → v2 key 持久化 + 本地快取 |
| 2 | **飛機上、無網路也能改** | v1 純雲端，離線全廢 → v2 offline-first，連線後自動同步 |
| 3 | **多人同改不互相覆蓋** | v1 last-write-wins 整份覆蓋會掉資料 → v2 欄位級合併 + 衝突保護 |
| 4 | **帳本真的能管預算** | v1 只記帳 → v2 預算上限 + 分類統計 |
| 5 | **行程隨手拖、行前不漏帶** | v1 只能靠時間排序 → v2 拖曳排序 + 打包清單 |

### 2.1 模組圖

```
┌─────────────────────────── PWA (React + Vite) ───────────────────────────┐
│  UI 層      行程 / 帳本 / 清單 / 相簿 / 設定（5 tabs，沿用 v1）             │

│  ────────────────────────────────────────────────────────────────────── │
│  持久層     IndexedDB（本地真實來源） ←→ 同步引擎 ←→ Supabase（雲端）        │

│             - 讀取：先讀 IndexedDB（秒開）→ 背景拉雲端 → 合併               │
│             - 衝突：欄位級 last-write-wins by updatedAt（見 F-03）          │
└──────────────────────────────────────────────────────────────────────────┘
        │                                   │
        ▼ Realtime 訂閱                      ▼ HTTPS
┌──────────────────┐              ┌──────────────────────────┐
│ Supabase         │              │ Vercel Serverless        │
│ - trips 表(jsonb)│              │ - /api/flight  航班時刻   │
│ - Realtime       │              │ - /api/rate    即時匯率   │
│ - Storage(P2相簿)│              │ （金鑰只在 server 端）     │
└──────────────────┘              └──────────────────────────┘
```

## 3. 使用者旅程總覽

| 階段 | 流程 |
|------|------|
| **首次啟動** | 開站（無 trip 參數）→ 產生強 key → 寫入網址 + **存入 localStorage** → 載入 SAMPLE 範例 → 引導去「設定」分享連結 |
| **再次開啟（同裝置）** | 網址有 trip 參數 → 用該 key；網址沒有（PWA 捷徑）→ **從 localStorage 還原上次 key**（修正 v1 洗掉 bug）|
| **旅伴加入** | 收到網址 → 點開 → 讀同一 trip → 即時看到內容、開始共編 |
| **日常編輯** | 任何修改 → 先落 IndexedDB（畫面即時）→ 入佇列 → 連線時上推；旅伴端 Realtime 收到後欄位級合併 |
| **離線使用** | 飛機/無網 → 照常編輯（IndexedDB）→ 頂部顯示「離線・N 筆待同步」→ 連線後自動補推 |
| **回國結算** | 帳本看分類統計 + 預算達成率 + 自動結算誰付誰 |

## 4. 功能規格詳述

> 標記：🔧 = 修 v1 問題；🆕 = 新功能；♻️ = v1 沿用（本版不動）

### 4.1 同步與資料層（本版重點）

| 編號 | 功能 | 規格 | 錯誤處理 |
|------|------|------|----------|
| **F-01** 🔧 | **Trip Key 持久化** | `getTripKey()` 改為：①網址有 `?trip` → 用之；②無 → 讀 `localStorage['sakura.lastTrip']`；③都無 → 產生新 key。任何情況都把現用 key 寫回網址 + localStorage。PWA `start_url` 改 `/`，靠 localStorage 還原 | localStorage 不可用（無痕）→ 退化為 v1 行為並提示「此模式重開可能需重貼連結」 |
| **F-02** 🔧🆕 | **Offline-first 持久化** | 以 IndexedDB（dexie）為本地真實來源。讀：先 IndexedDB 秒開，背景拉雲端合併。寫：先寫 IndexedDB → 推入同步佇列 | IndexedDB 配額滿 → 提示並降級為記憶體模式 |
| **F-03** 🔧 | **欄位級衝突合併** | 資料模型改為帶 `updatedAt` 的可合併結構（見第 5 章）。合併規則：以**項目為單位**比 `updatedAt`，新者勝；陣列以 `id` 為鍵做 union，不再整份覆蓋 | 同一項目同時改 → 取較新 `updatedAt`，並在該項目標記「⚠ 剛被旅伴更新」3 秒 |
| **F-04** 🔧 | **同步狀態列** | 頂部 header 顯示同步狀態：`已同步` / `同步中…` / `離線・N 筆待同步` / `同步失敗・重試` | 連續失敗 3 次 → 顯示紅點 + 「重試」按鈕，不靜默吞錯（修 v1 只 console.error）|
| **F-05** 🔧 | **不打斷輸入** | Realtime 回寫時，若使用者正在編輯某欄位（focus 中），該欄位延後套用，避免 v1 打字打到一半被覆蓋 | — |
| **F-06** 🔧 | **強 Trip Key** | key 長度由 8 → 22 字元（≈128-bit，用 `crypto.getRandomValues`），降低被掃描/碰撞風險 | — |
| **F-07** 🔧 | **寫入驗證 + 大小上限** | 上推前驗證資料 schema 與大小（jsonb < 1MB）；超限提示精簡資料（如相簿移至 Storage）| 驗證失敗 → 不上推、提示使用者 |

## 5. 資料模型

### 5.1 Supabase 表（不變結構、改用法）

```sql
-- 沿用 v1 的 trips 表，data 內部結構升級為可合併模型
create table if not exists trips (
  id text primary key,          -- 22 字元強 key（F-06）
  data jsonb not null default '{}',
  writer text,                  -- clientId，避免回寫自己
  updated_at timestamptz default now()
);
```

> **安全強化（F-06/F-07）**：RLS 維持匿名可存取（無登入模式），但靠 22 字元 key 當存取邊界。Phase 2 評估加 `pgcrypto` 或 Edge Function 做 rate-limit。

### 5.2 `data` JSON 結構（v2，每個可變項目帶 `updatedAt`）

```jsonc
{
  "schemaVersion": 2,
  "tripName":  { "v": "九州・沖繩之旅 🌸", "updatedAt": 0 },
  "startDate": { "v": "2026-06-10", "updatedAt": 0 },
  "endDate":   { "v": "2026-06-16", "updatedAt": 0 },
  "rate":      { "v": 0.21, "updatedAt": 0 },
  "budgetJPY": { "v": 0, "updatedAt": 0 },        // 🆕 F-23
  "travelers": ["我"],
  "flights":  [ /* {id, label, flightNo, from, to, dep, arr, est, updatedAt} */ ],
  "days":     [ /* {id, date, city, lodging, updatedAt, items:[
                     {id, time, title, type, note, order, updatedAt} ]} */ ],  // order: 🆕 F-12
  "expenses": [ /* {id, desc, amount, currency, paidBy, split, category, date, updatedAt} */ ], // category: 🆕 F-22
  "food":     [ /* {id, name, meta, done, updatedAt} */ ],
  "shopping": [ /* {id, name, meta, done, updatedAt} */ ],
  "packing":  [ /* {id, name, done, updatedAt} */ ],   // 🆕 F-31
  "albums":   [ /* {id, label, url, updatedAt} */ ]
}
```

### 5.3 合併規則（F-03）

| 資料形態 | 合併方式 |
|----------|----------|
| 純量欄位（tripName/rate/budget…）| 比 `updatedAt`，新者勝 |
| 陣列（days/expenses/items…）| 以 `id` 為鍵做 union；同 id 比 `updatedAt`；刪除以 tombstone（`_deleted:true`）標記，避免「刪了又被舊資料復活」|
| `travelers` | 字串陣列，做 union（不太會衝突）|

### 5.4 v1 → v2 資料遷移

| 規則 | 說明 |
|------|------|
| 偵測 | 載入時若無 `schemaVersion` 或 = 1 → 跑 migrator |
| 動作 | 把舊純量包成 `{v, updatedAt:0}`；陣列每項補 `updatedAt:0`、items 補 `order`（依現有排序）、補空 `packing` |
| 安全 | 遷移前先把原始 data 備份到 `99-Archive` 概念的 `data._v1backup`（一次性）|

## 6. 技術選型決策

| 決策 | 方案 | 理由 | 費用 |
|------|------|------|------|
| 本地持久化 | **Dexie (IndexedDB)** | offline-first 真實來源；比 localStorage 容量大、可結構化查詢 | 免費 (MIT) |
| 同步模型 | **欄位級 LWW + tombstone**（非 CRDT）| 旅遊共編衝突量低，LWW 足夠且實作成本低；CRDT 過度設計 | 免費 |
| 拖曳 | **@dnd-kit** | 觸控友善、無障礙佳、體積小 | 免費 (MIT) |
| 樣式 | **Tailwind 建置版** | 移除 CDN production warning、可 tree-shake | 免費 |
| 圖表（分類統計）| **純 CSS 橫條** | 不引第三方圖表庫，零依賴零成本 | 免費 |
| 測試 | **Vitest** | 與 Vite 同生態、零設定 | 免費 |
| AI 查詢 | Claude + web_search（沿用）| 已驗證可用；模型字串集中為設定 | 用量計費 < $1/趟 |
| iOS 上架（P3）| **Capacitor** | 直接包現有 Web，不重寫 | 免費 (MIT)；上架需 Apple 開發者 $99/年 |

## 8. 技術風險與對策

| 等級 | 風險 | 對策 |
|------|------|------|
| 🔴 高 | 同步合併寫錯 → 反而掉資料（比 v1 更糟）| F-62 對合併邏輯寫完整單元測試；遷移前備份 `_v1backup`；灰度先在自己行程驗證 |

| 🟡 中 | 拖曳排序與 time 排序邏輯打架 | 明確規則：一旦使用者手動拖過，該日改以 `order` 為準 |
| 🟢 低 | 即時匯率 API 失敗 | 一律可手動填，不阻斷 |
